# SEO変更ログ

`npm run growth`（および毎朝のGitHub Actions）が、その日の判断を1ファイルずつここに書き出します。

## なぜ残すのか

SEOの改善は、変更してから結果が出るまでに数週間かかります。1か月後に順位が動いたとき、
何を変えたのか思い出せなければ、良かったのか悪かったのかを判断できません。

「変更」と「結果」を突き合わせられる状態にしておくことが、改善を続ける前提になります。

## ファイル形式

`YYYY-MM-DD.md` で、次の項目を持ちます。

| 項目 | 内容 |
| --- | --- |
| `date` | 実行日 |
| `target` | 改善対象のURL、またはカテゴリ |
| `rule` | どの判定ルールで選ばれたか（A〜E、または内部リンク不足など） |
| `keyword` | 対象記事の主軸キーワード |
| `data_source` | `search-console`（実データ）か `site-state`（サイト内の状態のみ） |
| `action` | 実施する内容 |
| `reason` | そう判断した根拠 |
| `before` | 変更前の数値 |
| `expected_effect` | 想定している効果 |
| `next_action` | いつ何を見て判断するか |
| `result` | 後日、実際どうなったかを追記する |

## 使い方

`result` は空欄で生成されます。`next_action` に書かれたタイミングで結果を確認し、
**同じファイルに追記してください。** ここが埋まっていないと、判断の精度は上がりません。

## 判定ルール

| ルール | 条件 | 対応 |
| --- | --- | --- |
| A | 表示回数100以上でCTR 2%未満 | title / description の見直し |
| B | 平均掲載順位 11〜30位 | 内容追加、内部リンク強化 |
| D | クリック10件以上 | 派生キーワードの記事を追加 |
| E | 表示回数10未満 | 統合・リライト・削除の検討 |

Search Consoleが未設定の期間は、内部リンク数とカテゴリごとの記事数から判断します。
