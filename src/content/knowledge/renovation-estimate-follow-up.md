リフォームの見積もりを提示したあと、顧客からのリアクションが途切れがちだと感じていませんか。  
受注につながるフォローが抜け落ちると、潜在的な売上機会を失う可能性があります。本稿では、シクミベースが提供する「リフォーム反響OS 30」を活用し、**受信確認・現調前情報回収・案件台帳・未対応通知・見積後3回フォロー・KPI測定** の６要素で構成されるフローを設計・実装する手順をご紹介します。

## 結論：見積フォローは「受信確認→情報回収→台帳登録→未対応通知→3回フォロー→KPI測定」の一連フローで設計し、シクミベースの支援で実装すると抜け漏れ防止が目的になります

## 最初に可視化する業務

| 項目 | 内容 |
|------|------|
| 受付経路 | Webフォーム、電話、LINE 等、利用している経路を列挙 |
| 受付時刻 | 問い合わせがあった正確な日時 |
| 担当者 | 初回対応者および所属チーム |
| 案件状態 | 「新規」「情報取得待ち」「見積作成中」「フォローミッション中」など |
| 次回行動日 | 次にコンタクトすべき予定日 |
| 失注理由 | 案件が失注した際に記録すべき理由 |

これらは **案件台帳** に必ず保持させます。台帳必須項目例は「受付日時」「流入元」「氏名・連絡先」「相談対象」「希望時期」「担当者」「案件状態」「次回行動日」「最終接触日」「失注理由」です。  
詳細な設計例は[リフォーム会社の問い合わせ管理｜取りこぼしを見つける設計手順](/knowledge/marketing/renovation-inquiry-management/)をご参照ください。

## 実装手順

1. **対象フローの選定**  
   抜け漏れが懸念される工程（例：見積提出直後の追客）だけを対象フローとして決めます。

2. **入力項目の定義**  
   - 受付時に自動返信メールで「お問い合わせありがとうございました。担当者より○日以内にご連絡いたします。」とだけ伝え、金額や工期は確約しません。  
   - 現調前情報（物件所在地・施工希望箇所・予算感等）は担当者が手入力できる画面で取得します。

3. **担当割り振り**  
   - 受信確認は自動通知で担当者へ即時アラート。  
   - 情報回収と台帳登録は担当営業が完了チェックを入れることで完了扱いとなります。

4. **完了条件**  
   *受信確認* が完了したら「未対応通知」タイマーが開始し、指定期間内に次のステップへ進まなかった場合は警告が出ます。  
   *情報回収* と *台帳登録* が揃ったらフローは次段階へ遷移します。

5. **例外時の処理**  
   顧客から追加質問や変更依頼があった場合は例外として扱い、担当者がステータスを「再調整中」に変更します。個人情報は権限を持つ担当者のみが閲覧できるように管理し、変更や削除は上長の承認を得て実施します。

6. **見積後フォロー設計**  
   フォローは計３回実施しますが、送信間隔・文面・停止条件は **設計時に会社ごとで決める** 必要があります。各フォローは人が最終承認できる形で設定します。

## KPIの定義と見方

| KPI | 定義 | 集計単位 |
|-----|------|----------|
| 初回返信時間 | 問い合わせ受領から担当者による初回返信までの平均時間（分） | 月次 |
| 未対応数 | 「未対応通知」状態が残っている案件数 | 日次 |
| 次回行動日設定率 | 全案件に対して次回行動日が設定されている割合（％） | 月次 |
| フォロー実施率 | 見積提出後に設計した３回フォローうち実施できた回数の平均（最大３） | 月次 |

各指標は「総和 ÷ 件数」で算出し、月単位で比較します。KPI は **判断材料** として活用し、単独で結果を評価しないよう留意してください。成果保証は行いません。

## 自動化しない判断

以下のような局面では自動フローだけでは適切な判断が困難ですので、人による最終確認を必須とします。

* 金額が高額になる案件  
* 特殊工法や素材が関係する案件  
* 標準外の契約条件（支払条件・保証期間など）  
* クレームやトラブルが発生したケース  
* 個人情報（住所・金融情報等）の取り扱い変更が必要な場合  

これらは例外として扱い、担当者が手動でステータス変更や追加確認を行います。

## 向いている会社・先に別課題へ取り組む会社

### 向いているケース
* 複数チャネルから問い合わせがあり、現在は Excel 等で属人的に管理している。  
* 見積提出後の顧客応答率が低く、原因分析やフォロー体制の標準化が求められている。  
* 社内で「誰がいつ何をしたか」が把握できず、未対応案件が散在している。

### 先に別課題へ取り組むべきケース
* 基本的な問い合わせ受付自体が整備されておらず、まずは Web フォームや電話応答体制の整備が必要。  
* 業務マニュアルや標準作業手順書が未整備で属人化が深刻な場合は、【属人化を解消する業務マニュアルの作り方】(/knowledge/shikumika/gyomu-manual-tsukurikata/) の策定から始めてください。  
* デジタルツール導入経験が乏しく、社内教育や IT 環境整備が急務の場合はまずインフラ整備を優先します。  

参考として、中小企業の AI 導入初期ステップについては[中小企業のAI導入、まず何から始めるべきか](/knowledge/ai/chusho-kigyo-ai-donyu/) をご覧ください。

## まとめ

- 見積フォロー抜け漏れ防止は「受信確認 → 情報回収 → 案件台帳 → 未対応通知 → 3 回フォロー → KPI 測定」の一貫フローで設計する。  
- 対象フローは１本に絞り、各ステップの入力責任者・完了条件・例外処理を明文化して可視化する。  
- KPI は初回返信時間・未対応数・次回行動日設定率・フォロー実施率の４つで構成し、月次で集計して判断材料とする。  
- 高額案件やクレーム対応など、人判断が不可欠な局面は自動化対象外として例外扱いにし、人レビューへ引き継ぐ。  
- 現状の問い合わせ管理体制や業務マニュアル整備状況によって導入適否を判断し、必要なら先行課題解決へ取り組む。
